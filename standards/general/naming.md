# 命名与文件职责


## 命名与接口

- 用已有领域术语，同一概念同一词；名字匹配作用域，单位、端点和副作用可辨认。`Data`、`Info`、`Manager` 不是禁词，但不能掩盖不清楚的职责；读取操作不能悄悄创建、消费或持久化。
- 调用点有歧义时，优先现成类型、枚举、结果结构、具名参数或常量；不为每个值包类型，不用任意字符串替代有限选项。
- 参数多或布尔标志只是检查线索，不是缺陷。明确布尔属性可保留；已发布接口不能因审美变更，也不能仅凭仓内无调用判定可删。


## 文件与项目命名

文件按紧密相关的概念组织，避免大杂烩和每类一文件的机械拆分。目录、文件后缀、大小写、成员前缀、接口类和指针别名采用目标仓声明的取值，不在通用规范固定。

名字长短匹配作用域；下标 `i` 合理，公开 API 不删字母缩写；单位和布尔含义明确，如 `timeout_ms`。同一文件不混用命名风格。`const` 不意味着编译期常量，不仅凭 const 改用常量命名。

C++ 标识符必须遵守语言保留名规则：下划线紧接大写字母、包含双下划线的名字在任何作用域都保留；历史惯例不能豁免。存量改名先核消费者、兼容与授权。

正例：`timeout_ms` 明确单位，`is_enabled` 表达布尔属性。
反例：读取操作叫 `get`，实际却创建持久化记录；为跟命名风格而破坏既有公共 API。
