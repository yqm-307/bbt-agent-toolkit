# C++ 通用写法

目标仓真实语言版本、错误协议、依赖、formatter 与兼容约束优先。不固定语言标准、第三方库、测试框架或协程模型，不为满足风格擅改构建开关。已有文件先跟周围，不顺手全库重排；已证实泄漏、悬空、数据竞争和语言错误不能因存量豁免。

## 表达与对象

简单类直接构造，纯数据用 struct；复杂对象必须用 class 封装可变状态和不变量，不能仅把关键字改成 class 后全部 public，也不鼓励逐字段 getter/setter。内部状态多或对外接口多，尤其字段数或公开操作数任一 **> 10**，应按复杂对象审查，两项不相加；低于阈值仍可能复杂。纯数据记录、wire 值视图、Stats/Options 快照是职责明确的例外，名字不自动豁免。字段数是直接声明的数据成员数，公开操作数按直接声明的公开函数（含构造、析构及重载各一项）计数，静态常量不算可变状态；继承、宏生成的成员另行审查。对象职责原则见 [代码品位](../general/code-taste.md#对象负责自己的状态)。

正例：`class Queue { public: void Close(); private: bool closed_; };`；纯值 `struct Point { int x; int y; };`。
反例：二十字段的状态 struct 配合外部持锁修改；同样字段改成 class 后仍全部 public。

成员使用前初始化，按声明序初始化。只读用 const，空值用 nullptr。类型已在右侧写明或过长时多用 auto（工厂、结构化绑定、迭代器、lambda），但不隐藏所有权或数值范围。时间和时长优先用 `std::chrono`。

标准库有成熟能力时先复用；不足时复用项目已选、成熟且适合的依赖。新增依赖评估许可、安全、平台、维护、体积和退出路径。命名空间按模块组织，层数与命名取值由项目规定。

外部输入用运行时校验，不靠 assert。无符号类型不代表输入已验证为非负；转换前核符号和目标范围，构造入口也不例外。核长度、范围、溢出和返回值；遵守目标错误协议，失败不留下未声明的半份修改。

控制流、调用点、注释和抽象分别沿用 [代码品位](../general/code-taste.md)、[命名](../general/naming.md) 和 [文档](../general/documentation.md)。具体候选排版见 [格式](format.md)。

## 值与资源

优先值语义和自动存储期；需要动态对象才用 `unique_ptr`，确需多方共同延寿才用 `shared_ptr`。裸指针和引用可借用，必须明确可空性、使用期限和失效条件。
`shared_ptr` 保证控制块管理的寿命，不保证被指对象线程安全；环形共享用弱引用或改所有权图。不要把裸指针重复包装成独立控制块。

资源使用已有 RAII 包装；底层封装内部的 `new`、`delete`、`close` 并非一概禁止，但每条失败/早退路径必须有唯一可靠的释放责任。普通调用方不要重复手工清理。值对象或智能指针能解决时不另建管理框架。

## 构造与复制

- 简单对象直接构造，不强制工厂、私有构造或堆分配。
- 构造建立可用的不变量，不调用虚函数。构造不能报告可恢复失败且项目不使用异常时，考虑返回明确失败结果的工厂；避免调用者必须记住再 Init 才可用的半成品。
- 单参数转换构造及转换运算符通常 `explicit`；复制/移动构造不是机械加 explicit 的对象。
- 默认让成员负责资源（Rule of Zero）。资源语义需要时明确删除复制或定义移动；不为所有类型机械补齐五个特殊成员函数。
- 多态删除需要安全析构接口；覆盖虚函数写 `override`，不要重复写 `virtual` 与 `override`。

## 参数和返回

优先返回值。不可空借用通常引用，可空借用用指针；小型输入按值，大型只读输入用 const 引用。输出参数放后，说明失败时是否保持原值。

多结果用语义清楚的结果结构或项目已有 `tuple`/`Result` 表达。确有复用缓冲或兼容需求时，可同时提供出参版与返回值版，两者行为一致，返回值版复用同一实现而不复制逻辑；是否提供双版本、字段与错误顺序按项目契约，不给所有接口机械补齐。

view、span、指针、引用不延长底层对象寿命。保存输入供调用后使用时，优先持有值或所有权；仅把引用改成指针不能修复悬空。

## 回调

逃逸 lambda 优先显式捕获。复制裸指针、`this`、view 仍然只是借用；证明对象活过任务，或捕获值/所有权。同步算法中短小的默认捕获不自动构成问题。

```cpp
// 形状示例：仅表达捕获策略，不假定某个队列 API。
// 好：任务拥有字符串数据。
auto task = [text = std::string("ready")] { return text.size(); };
// 坏：返回 [&local] 的任务，local 已随创建函数退出而销毁。
```

## 错误与 noexcept

参考来源 Google 默认不使用 C++ 异常；集成已有使用异常的代码，不擅自禁用异常或改写公共协议。错误码、Status、optional 各有表达边界，不在通用规范里强制 `0/-1/1` 或新增 Abseil 依赖。
边界检查失败应有可观察结果，不只日志、不吞错。修改状态先验证；多步操作需说明失败后保持或回滚到什么状态。
`noexcept` 是不抛承诺，不是性能装饰；检查所有可调用路径，包括分配、锁和用户回调。析构不得让异常逸出。

## 自给与依赖

头文件独立包含可编译，包含直接使用的符号声明。头保护形式按项目约定。include 按对应头、系统/标准库、其他库、本项目分组，组间空行；平台条件包含按实际依赖保留。以库形式对外时优先使用尖括号项目相对路径，纯应用可用引号，同项目保持一致。实现中冗长限定名重复时，可在最小作用域使用 using namespace；遇同名冲突或来源不清改用具名 using 或命名空间别名。`.cc` 先包含对应头，再包含它自己使用的其他符号；不依赖传递包含。不要在头文件全局写 `using namespace`，不要前向声明不拥有的第三方或标准库实体。
项目自有类型的前向声明仅在依赖/编译成本值得时选择，不为了前向声明把值成员改成动态分配。

**声明与实现默认分离**：声明（类定义、函数签名）放头文件，实现放对应 `.cc`；不把非平凡函数体写在头文件里。移动实现主要降低消费者重编译成本与暴露的实现依赖；需要真正隐藏成员或稳定 ABI 时需另用 pimpl 或抽象接口。`inline` 是 ODR/链接说明符，不保证编译器内联。

建议：接口头只留读者要看的契约，实现细节不挤占阅读，降低认知负担。这是建议性约束，有合理理由可以例外，说明一句即可。

实现建议这样放：
- **非模板**：函数体放对应 `.cc`。头文件宜只留极简体：一行、无分支无循环、不加锁不分配的 getter/setter，以及语言要求在客户端 TU 可见的 `constexpr` / `consteval`、`inline` 变量、`static constexpr` 成员、`= default` / `= delete`。
- **模板**：主头放类与函数声明；定义放进同目录的单独实现头，主头末尾 include（命名按目标仓约定，如 `*_impl.hpp`）。避免把模板函数体写在类体内，或堆在主头后半截让读者翻过一屏才看到接口。仅在单个 `.cc` 实例化的模板可留在该 `.cc`。
- header-only 指不产出库文件，不等于把实现写进接口头：有 header-only 策略时，函数体也宜进实现头（非模板标 `inline`），与声明头分文件。

判断“极简”：写成一行仍一眼读懂即可；需要换行、有分支、循环、锁或分配，就建议移走。

不太推荐的写法：在接口头直接写非极简的函数体，即使当前只有一个 `.cc` 包含它；或在类体内联一段带锁的成员函数。存量代码不因本次改动连带搬迁，新增和改动的部分按此建议写即可。

## 特性选择

语言版本、RTTI、异常和测试入口来自目标构建配置，不把一个仓库的语言版本、RTTI 开关、构建系统或测试框架推广成通用要求。禁止为满足风格擅改构建开关。

- 模板用于确有多类型复用的代码；普通函数足够时不用元编程。错误信息、实例化成本和调用点理解成本也算成本。
- `auto` 在初始化器明显、迭代器繁琐或避免错误时合适；不要隐藏影响所有权、数值范围的关键类型。
- 重载应语义一致，运算符含义应符合通常预期。默认实参不用于虚函数，不藏动态副作用。
- 接口、工厂与继承是否值得按 [职责与抽象](../general/code-taste.md) 判断，不在语言特性页另设一套门槛。
- 宏的语义边界见本页“运算符与宏的边界”。
- Google 对 C++20 modules、标准库部分设施有额外限制；触及限制或新语言特性时查上游对应章节，不凭“现代 C++”一律允许，也不凭本 skill 未列出就禁止。

## 验证

使用真实目标标准编译，保持无新增警告；不要用新增 `-Wno-*` 掩盖问题。验证修改的公开头可独立包含，模板有实际实例化检查。新测试按目标项目的发现/注册机制加入，选择覆盖成功、错误、边界的最小充分测试。
代码格式检查不证明语义正确；编译成功不证明并发安全。只声称真实执行覆盖的部分。

怀疑旧构建产物或切换依赖版本时，使用独立构建目录，或先证明已有目录与当前源码、依赖一致；不把源码时间戳当成依赖身份。CMake 的 `<包>_DIR` 缓存可能保留旧路径，仅改 prefix 或得到 `no work to do` 不证明已切换；核对 cache、实际编译/链接和必要的加载路径，不要求无疑点时每次重建。

## 原子、线程局部与静态寿命

共享协议、回调、等待与关闭的语言无关要求见 [所有权与并发](../general/ownership-and-concurrency.md)。C++ `volatile` 不建立 happens-before，不消除数据竞争。版本号原子或读取后重试不能补救普通 payload 的并发读写；release/acquire 只在所有冲突访问确实被 happens-before 排序时有效，不给反复覆写的非原子载荷自动免责。修复前追踪所有读写路径，不机械替换类型。

Google 允许项目认可的 C++20 协程库，不鼓励业务代码自造 promise/awaitable；不能因某项目使用栈式协程而禁止所有项目的 co_await。业务遵循已采用框架。

Google 要求静态存储期对象平凡析构，包括函数局部 static；局部 static 可动态初始化，不代表允许任意析构。非平凡全局对象和跨翻译单元依赖容易在启动/退出期访问失效对象。优先将服务状态交给显式寿命 owner。故意不析构是须说明的特殊设计，不作默认修法；区分风格偏差与真实退出竞态。

## 公共边界与易用接口

公开头不泄漏内部类型、第三方物理栈、异常类型或线程模型；无法隔离时明确兼容影响并在审查中核对。公共头文档承诺和可观察实现一致。公开类型有可定位的声明头，内聚小类型可共处；存在非内联实现时配编译单元，接口、目录与命名空间一致。

声明与实现按职责分离；空构造、空析构、单语句访问器和短小转发不机械外移。纯算法、类型工具、无状态小组件可 header-only；稳定 ABI、重状态、I/O 或编译成本需要时保留编译单元，不为减少文件把不同责任揉进同一头。

正例：RPC 公共头只暴露协议契约和稳定错误类型，HTTP 类型留在实现或适配层；调用者无需理解内部传输栈。
反例：为测试方便把内部连接类加入公共头，或承诺线程安全却不说明同步范围；类体中塞入二十行带锁实现，模板定义挤占接口阅读。

对外接口简洁、易用，让使用者少关心细节，能快速写 demo 也能用于正式代码。一个接口一个含义，职责类型过多时先评估再拆。只用一次的辅助类型优先放所属类内部；可复用或抽出确实更易理解才单独成类。

正例：服务器复用真正独立的连接类型；只服务本服务器的路由表与额度状态保留内部结构。
反例：为一次流程新建只被一个类用的 Manager、Helper、Context，或用 `do_work(mode, flag, ...)` 切换多个含义。

## 运算符与宏的边界

运算符重载必须语义自然、符合直觉，例如缓冲流的 `<<`/`>>` 表达写入/读出，不为炫技反转通常含义。

宏只做语言机制无法合适表达的语法糖和声明元数据；能用内联函数、模板、constexpr 表达就不用宏。展开可一眼对应意图，文档写清用法、展开含义和注意事项，不要求使用者读宏定义。公开宏加项目唯一模块前缀，不污染命名空间，不重复求值、不制造不平衡语法、不生成难定位符号。不在宏中隐藏 return、goto、throw、锁获取/释放、所有权转移；项目明确文档化的语法扩展须单独声明例外，不推广为通用许可。

## 来源与采纳边界

来源：Google C++ Style Guide，https://google.github.io/styleguide/cppguide.html 。重点章节为 Naming、Formatting、Header Files、Classes、Functions、Ownership and Smart Pointers、Lambda Expressions、Exceptions、Static and Global Variables、Coroutines。在线原文未固定快照，触及新限制时核对应章节，不凭现代 C++ 一律允许，也不凭本文没列出就禁止。

Google 或标准允许的其他形式不自动是安全缺陷。自然语言、语言版本、错误与构建协议、命名和机械风格以项目声明为准，不强制额外结果库、禁异常或某种协程。完整例运行与项目验证分开，正反例不虚构库 API。维护时保证入口够用、规则唯一、来源可恢复；不添加函数行数/参数数硬门槛，不把一个职责机械等同于每个附属类型独立文件，不把专用实现换名伪装成通用原则。

[实现示例](examples/readability-examples.md) 使用 C++17，仅为教学，不代表目标项目基线。审查先正确性、安全、契约，再一致性和可读性，最后有证据的性能问题；风格偏差不是自动 bug。
