# 测试方法目录与条件决策表

以下是用例设计参考，不是测试种类的全量清单，也不是每次都要执行的套餐。按真实契约确定预期，按失败机制选方法；同一用例可以覆盖多个方法，但须说清它实际区分的错误。边界案例的「可检出缺陷」须用该输入分别代入正确与变异条件核对，不因贴了 M2 标签就自动成立。

## 测试层级路由

先定位风险在哪个边界，再选择能直接观察它的最低层级。层级不是质量排序；选更高层级的理由应是低层级无法表达或无法观察该风险。

| 风险位置 | 首选层级 | 需要上移的信号 |
|---|---|---|
| 单函数分支、纯计算、输入校验 | 单元测试 | 结果依赖真实序列化、时钟、线程或外部边界 |
| 请求／响应、序列化、错误格式、旧消费者 | 契约测试 | 需要同时验证多个模块或真实传输行为 |
| 数据库、文件、队列、外部服务适配 | 集成测试 | 适配器之外的编排、重试或跨服务终态才是风险 |
| 浏览器事件、渲染、轮询、焦点和真实网络接线 | 浏览器／端到端测试 | 无法稳定控制环境时，先在低层级覆盖确定性逻辑并明确视觉／环境缺口 |
| 锁、竞态、异步回调、去重和恢复 | 可控集成测试 | 需要测吞吐、容量或长时间稳定性时，另按性能契约进入负载测试 |

同一风险可以有多个层级的案例，但每个案例都应说明它新增观察了什么；不要用高层级案例重复覆盖低层级已经能确定的纯逻辑。

## 方法目录

| ID | 方法 | 适用信号 | 生成案例的动作与应观察的错误 |
|---|---|---|---|
| M1 | 等价类划分 | 有输入域、校验、分类或错误分支 | 从各有效／无效类各选代表值；核对输出与拒绝语义，避免只测有效值。 |
| M2 | 边界值分析 | 阈值、范围、长度、分页、时间窗口 | 测界值及两侧（域允许时）；区分 `<`/`≤`、空／满和溢出等错误。 |
| M3 | 条件决策表 | 多条件联合决定结果，如权限、折扣、特性开关 | 列条件与预期结果，优先覆盖独立改变结果的组合、冲突与兜底；不要猜业务优先级。 |
| M4 | 状态迁移／事件序列 | 请求结果依赖前态、重试、撤销或幂等 | 画出允许／禁止的迁移，测试前态→动作→后态、重复动作和无效顺序。 |
| M5 | 成对组合与交互 | 多独立配置维度，穷举过大 | 先确定各维度及已知高风险交互，再选覆盖所需组合；成对不保证发现三元以上交互。 |
| M6 | 性质／不变量 | 可用跨输入的恒定约束描述正确性 | 检查例如守恒、排序、上下界、幂等；性质必须来自契约，不能由实现倒推。 |
| M7 | 变形关系 | 单个输入缺可靠判定器，但输入变化应使输出遵循关系 | 构造变换与预期关系（如重复同一幂等请求结果不变）；关系需有契约依据。 |
| M8 | 故障与恢复 | I/O、超时、外部依赖、事务或资源生命周期 | 在隔离环境注入失败，断言错误传播／回滚／重试边界／资源释放及失败后的可观察状态。 |
| M9 | 并发／时序 | 共享状态、竞争、去重、锁、异步回调 | 控制交错、时钟和重复事件，检查不变量、终态与副作用次数；一次压力测试成功不证明无竞态。 |
| M10 | 契约／兼容性 | 公共 API、序列化、跨模块消费者、版本迁移 | 用旧调用者／样本与新实现对照，核对格式、默认值、错误语义和兼容边界。 |
| M11 | 安全负例 | 身份、权限、隔离、敏感输出或不可信输入 | 测拒绝访问、越权、恶意输入和无泄露；只在授权环境内构造输入。 |
| M12 | 变异测试 | 已有稳定、确定性的测试，怀疑断言过弱 | 对限定代码做小变异（如 `>=`→`>`），观察测试能否杀死；存活者先查等价变异／未覆盖分支，不把变异分数当发布门槛。 |

M1／M2／M3 等是测试设计方法，M12 是**反向检验已有测试敏感度**，不能替代预期行为的定义。变异体必须在隔离的临时工作区运行，不得把故意改坏的代码混入目标提交；超时、未编译、等价变异分别记录，不能全算作被杀死。性能／负载测试按性能契约与专用环境另定，本目录不替代它们。

## 条件决策表（方法选择）

**匹配策略：收集所有匹配行，先执行基础行，再按风险与预算增加行；不是首条命中。** 输入条件取「是／否／未知」；未知时只采用已知条件对应的方法，并记录需要补证的条件，不当作“否”。一行只给候选，不授予运行、改代码或访问系统的权限。

| 规则 | 可观察条件 | 候选方法 | 最少说明 |
|---|---|---|---|
| R0 | 有可验证的输入／输出或错误契约 | M1；有界值时加 M2 | 划分有效／无效类，区分关键边界。 |
| R1 | 两个以上条件共同改变结果 | M3 | 列真值与组合；未知的优先级停下查契约。 |
| R2 | 行为取决于前态或动作顺序 | M4；有可证明不变量时加 M6 | 涵盖合法、非法和重复转移。 |
| R3 | 配置／输入维度多且全组合不可行 | M5 | 先保留已知关键交互，再补成对覆盖。 |
| R4 | 输出很难逐个枚举，但有跨输入约束或关系 | M6 或 M7 | 写明性质或变形关系的权威依据。 |
| R5 | 存在外部故障、共享状态或时序 | M8；若有并发则加 M9 | 使用隔离环境，检查故障后的可观察状态。 |
| R6 | 面向旧消费者或存在权限／隔离边界 | M10；有安全边界则加 M11 | 核对兼容输入与拒绝路径。 |
| R7 | 关键测试已稳定但质量存疑，且有安全的临时工作区 | 可选 M12 | 限范围与时间，先调查存活变异而非追分。 |

无命中：如果只是纯格式／文档／配置改动且没有行为契约，按仓库相应解析／构建／smoke 检查，不强迫发明业务用例。若预期本身未知，**不能仅由决策表推出断言**；列出缺失契约并请求确认或查证。多行同时命中时按失败机制去重，挑最少能暴露本次风险的案例集；例如 R0 与 R1 同时命中时先保留有效／无效边界，再用仅改变一个条件的配对案例验证结果翻转，预算不足的候选明确列为未覆盖。高风险边界不得因低成本项已覆盖就省略。每个保留案例还要标出测试层级和断言观察点。

## 一例：年龄与激活状态

假设有明确契约：`eligible(age, active)` 仅在 `age >= 18` 且 `active` 为真时返回真；年龄仅接收非负整数，非法输入需拒绝。该例的真值与错误语义是**题设**，不是从实现反推。

- R0 → M1/M2：`age=17,18,19` 且 `active=true`，预期依次为假、真、真；`age=-1`、非整数按契约断言拒绝。
- R1 → M3：`age=18,active=false` 预期假；与 `age=18,active=true` 成对，区分忽略激活状态的错误。还应确认条件同时失败时的拒绝／返回语义，而不是凭示例推定。
- R7 → M12（可选）：隔离工作区把 `>=` 变为 `>`，`age=18,active=true` 应使现有测试失败；若测试仍通过，则检查测试是否实际执行并断言边界结果。此处是设计预期，未声称运行过变异工具。

若接口实际上允许 `age=-1` 并返回假，应先修正契约依据和用例；不能为了迎合目录而让测试与真实业务约定冲突。
