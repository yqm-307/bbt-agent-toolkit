# 代码测试用例设计

本 skill 是 QA 方法入口：按契约与风险选择、设计和精简行为测试。完整方法见 [测试用例设计](../../../agents/qa/references/test-design.md)，方法目录与条件决策表见 [测试方法](../../../agents/qa/references/test-methods.md)。只运行已确定的命令、发布放行和独立审查遵循目标仓现行规则。

## 适用范围

适用于新增行为、缺陷修复、回归遗漏、覆盖缺口，以及检查测试能否抓住具体错误；也用于减少重复、过长等待和不稳定测试。只运行已有测试命令时不重新设计用例；纯文档、格式或无行为配置改动不强迫发明业务案例。

## 最小流程

1. 读取契约、受影响代码和现有测试入口，区分预期来源与当前实现。
2. 写出前置条件、动作或事件、可观察结果、断言、契约依据和能区分的错误。
3. 选择能观察风险的最低且足够层级，优先复用已有案例；高风险交错使用受控事件、屏障或时钟。
4. 执行被授权的检查并记录候选版本、命令、结果和未验证原因；失败区分产品、测试和环境问题。
5. 高风险均有有效保护，或剩余风险已明确记录，且新增案例不再改变结论时停止。

本入口不复制角色正文；测试设计与方法文件是可复用角色资料，目标仓的具体命令、标签和门禁优先。
