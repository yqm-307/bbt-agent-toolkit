# mwc-chat-end — 结束聊天前的检查、选择与归档

用户想结束聊天时用：先替用户核对「能不能结束」，把检查点讲清楚，再给 1–4 选项让用户一次选定怎么结束。会话盘点、闭环判断和归档确认由当前主 agent 亲自完成，不得委托；必要的独立代码审查或专业执行可以委托，结果仍由主 agent 验证。

**本流程不当场提炼经验**：bad case 自动扫描记录，留在库里供以后使用（例如 `mwc-correct` 查重复错误时直接取）；经验提炼、prompt 与记忆更新属于用户另行决定的动作，不归本 skill，不在选项里出现。

## 目标与触发

用户说「结束聊天」「收尾」「预归档」「检查一下，准备归档」「归档吧」或点名本 skill 时执行。仅讨论、阅读或修改本 skill 不算结束指令。不自动触发，不给简单会话强加流程。

**结束指会话归档（WebUI，或官方 WebApp / 桌面端），不是另写 summary 文件。** 归档可恢复，不删除聊天记录、工作区或服务。

## 交互状态：独立流程，ASCII 展示

本 skill 独立运行，不依赖 OMH、DAG 工具或子代理编排。主 agent 用当前对话和内部 todo 维护状态，不另建状态文件；内部待办不算业务未完成项。

- 首次检查汇报、最终归档确认时，在结论后用短 ASCII 路径标明当前分支和等待点。只对已完成的动作标记 `[完成]`。格式见[检查点与状态示例](references/checkpoint.md)。
- **图只说明状态，不授予权限**：选择、写入和归档沿用下文各自的确认要求；等待时停在对应节点，不能把展示出来的后续步骤当作已经获准执行。
- **分支明确结束**：清理为空时标跳过。用户选择暂不归档则保留会话，归档入口受阻则说明手动操作方式，不把受阻画成完成。
- **恢复不重来**：用户只回复选择时，从当前等待点继续；上下文缺失先恢复本会话记录。用户新增事项或改变决定时，只使受影响结论失效，按下文重新确认，不沿用过期授权。

## 第一段：检查并汇报检查点

1. **圈定范围**：从本会话工具痕迹、交付目标与授权盘点产出和临时资源。上下文不足时用 `session_search` 补本会话记录；Git 状态与差异只是线索，不能把所有脏文件都归本会话。不做全盘扫描；非 Git 目录按不适用处理。
2. **核验适用项**（不适用的写明不适用，不扩大目标）：
   - 交付目标及必要验证已完成，有真实证据。
   - 本次应提交、推送、合并的变更达到约定状态。
   - 本次要求的部署、生效验证和运维记录已完成。
   - 目标内未完成事项已完成，或经用户明确取消、转交到可追踪去处；仅写进 summary 不算处置。
   - 本会话临时资源的现状：临时文件（scratch、一次性脚本、导出）、后台进程/端口/隧道、测试服务/容器、linked worktree 与本地分支。**此处只盘点并列清单，不动手清理**，是否清理由第二段用户选择决定；未确认归属的不列入清理对象，已核实收口的 worktree 与分支除外（见下条）。
   - 按[盘点细则](references/checkpoint.md#worktree-和分支盘点)对本会话碰过的仓跑 `clean` dry-run 盘点，分类由命令自动完成。只有已核实收口的 worktree 和分支可不受创建会话归属限制。进行中的对象只报告，清理仍须用户选择。
3. **记录 bad case**。主 agent 按[历史回顾细则](references/checkpoint.md#回顾本会话历史)回顾本会话，标明历史缺口。可定位的 bad case 按 `mwc-bad-case` 写独立 SQLite（`source=chat-end`），报告写入结果。这是自动行为，不判断、不征求许可；本流程不提炼经验、不更新 prompt 或长期记忆。
4. **复用证据，补缺不重跑**：已有审查、测试及验收内容未变且仍适用时复用，新变更只补查影响面；运行态等易变事实按风险只读刷新；未知或验证失败不算通过。
5. **确认归档入口**。读[归档执行入口](references/archive.md)并运行脚本 `check`，确认当前会话平台、会话 ID、profile、归档状态和 pin 状态。技术检查独立于业务检查。平台不支持或入口受限时仍可完成检查，汇报具体阻塞。

### 汇报格式

先报能否结束，再用[检查点短表](references/checkpoint.md#检查点汇报示例)列出结果，最后给出 1–4 选项。

> 请选：
> 1. **推荐：<本次具体动作，如「清理残留后结束」>**：agent 按上面盘点给出的综合方案，写明含哪些动作和对象。
> 2. **直接结束**：只归档，不做其它动作；这个选择本身就是归档确认，不再二次询问。
> 3. **清理残留后结束**：先清理上面列出的临时资源（含已核实收口的 worktree 与分支，不限创建会话），再请你确认归档。
> 4. **先不结束**：继续处理缺口，或取消结束。

- **1 恒为推荐项，位置不变**，由盘点决定：有残留就是「清理残留后结束」并写明对象；没有就是「直接结束」；有阻塞就是「先补缺口：<具体动作>」（不归档）。1 要写成具体动作，不能只写「推荐」，用户回「1」即可照做。2–4 固定不变，不因推荐而增删或改序。
- 清理清单为空时说明「无需清理」；不凭空造活，仍进入「最后一步：确认归档」。只有选 2（以及 1 展开成纯「直接结束」）不再二次确认。
- 有阻塞时 1 是先补缺口；用户仍选 2、3 的，带着缺口结束是用户的决定，归档可恢复，把遗留缺口原样写进结束回复，不隐藏风险。
- bad case 的扫描与写入结果在检查点中如实报告（数量、ID、历史覆盖），仅此而已：不附修复建议，不需要用户为它做任何选择；库里 open 存量明显堆积时可用一句话提「可以点名 `mwc-correct` 处理这些记录」，不把它做成收尾选项。
- 单纯归档入口受限：说「收尾已完成；自动归档受阻：<原因>」，按平台请用户手动归档（WebUI 侧栏归档；WebApp / 桌面端侧栏 Archive）。被 pin 挡住时先问是否 unpin，不自行解 pin。

## 第二段：按选择执行并归档

只在已经针对**当前会话**给出上面的汇报与选项，且用户随后明确选了 1–3（或「直接结束」「清理后结束」「按推荐」等同义回复）时执行。选 1 就先展开成它写明的具体动作，再按下面对应项执行。讨论方案时的「可以」不能充当选择。上下文缺失则查本会话记录，不猜。

用户回来期间若有实质变更、目标增加或证据失效，原结论失效：只补查变化部分，重新汇报并重新给选项。只有选择回复、无新增事项，不重跑全套检查或审查。

按选择：

- **4 先不结束，或选 1 而它写明「先补缺口」**：只处理缺口，不归档。处理完后只补查变化部分，重新汇报并重新给出 1–4，不沿用旧的选择或确认。
- **2 直接结束**：选择即归档确认，直接归档。选 1 而它写明的就是「直接结束」时同此处理，不再问第二遍。
- **3 清理残留**：只清理第一段列出的临时资源，清理后读回确认；不误停正式服务、不删回滚资产。已核实收口的分支与其 worktree 不是回滚资产（合并提交本身即回滚落点），git 对象部分对第一段列出的仓执行 `git-worktree-ops` 的 `clean --apply`（命令执行时重新盘点、只删安全集），读回其 actions/held 并汇报；安全集若超出第一段清单，如实说明增量。其余临时资源按清单逐项清理，清单外的东西一律不动。删除生产对象或其它缺授权动作，列明对象和影响后等用户决定。

选择只授权所选动作，**不附带提交、推送、部署或对其他会话的操作**；这些仍按原任务授权与对应门禁处理。按第一段清单清理已核实收口的 worktree 与分支不受创建会话限制。

### 最后一步：确认归档（选 2 除外）

选 3，或选 1 且它展开的动作含清理，这些动作都做完后，**停下来、不自动归档**，用一条短回复汇报结果和遗留项，并以这个问题结尾：

> 请选：**1. 立即归档本会话（默认）** / 2. 先不归档

用户回「1」（或「归档」「好」等明确同义回复）就立即归档，不再追问；回 2 就保留会话，说明随时可再说「归档吧」。这一步要求用户在动作完成后明确回应，选择阶段的回复不能顶替。若这期间用户追加了新事项，先处理新事项，再重新问这一句。

按[归档执行入口](references/archive.md)对确认过的当前会话运行脚本 `archive`，并按平台读回。读到 `archived` 为真且会话 ID / profile 一致后，才回复：

> **已结束并归档，本会话已闭环。**（附：本次执行了选项几，遗留项若有。）

归档过程中当前回复可以继续生成；不得为了看到该回复而自动恢复会话。已归档的重复请求只读确认，不再写入。

请求失败、超时或读回失败：说「归档尚未确认：<最短原因>」，保留待确认状态；先只读检查，不能盲目重发、直改数据库或假报闭环。用户手动归档的，能读回就验证，否则只说明尚未核实。

## 验证与边界

提示词行为的聚焦检查见 [tests/scenarios.md](tests/scenarios.md)：核对 bad case 记录口径、依据不足时的降级、ASCII 等待状态与授权边界。这些用例是验证输入与判定要求，不是已运行的模型评测结果；脚本自检也不能证明记录质量。新增或修改扫描记录方法时，报告实际做过的检查与尚未验证的真实会话效果，不把人工写出的示例算作行为证据。

维护本 skill 后运行脚本自检。`SKILL_DIR` 取当前加载的 skill 目录。

```bash
python3 "$SKILL_DIR/scripts/session_archive.py" self-test
```

脚本自检不发网络请求、不调用真实 CLI：覆盖平台识别与拒绝、压缩轮换后按 chat id 回退、WebUI 身份边界与压缩后 ID 保持、只读检查、精确写入、幂等、读回失败，以及 WebApp 侧的 pin 拒绝、确认 id 校验、adopted / 无 chat id 拒绝、CLI 计数校验与读回。真实接口 / CLI 变更另用一次性会话验证归档与恢复，不拿用户正在工作的会话做实验。

不会因为执行本 skill 自动放宽任何安全、提交或生产门禁。
