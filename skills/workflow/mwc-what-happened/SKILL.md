# mwc-what-happened — 发生了什么，下一步做什么

让用户几句话接上当前会话：我们之前在讨论什么、要做什么，最近发生了什么，现在做到哪一步，接下来先做什么。中途问或隔一阵回来都适用，不预设任务停了，也不假设用户记得上次聊到哪。

## 核对现状

1. 找到用户关心的主题，用最近相关的对话确认目标和关键决定。只在上下文不够时补查这段会话，不从头复述；需要重建跨会话的大范围历史时先用 `mwc-recall`。还在讨论就说还在讨论，别把方案说成已经开工。
2. 用最近的执行结果、实际产物或当前任务状态核对进度。区分还在做、在等什么、遇到阻塞、已停止、失败和已完成。某一步做完不等于整件事做完；没有新消息也不等于停了。待办、建议、子代理自述和旧摘要只算线索，不算完成。查不到现状就说最后确认到哪；有证据才说为什么停或卡住。
3. 只读核对，不为汇报重跑验证，也不启动、暂停、取消或恢复任务。在途工作不因这句询问而停下。若用户另有执行指令，按那条指令和已有授权处理。

## 下一步

用户问「接下来做什么」「下一步」，或现状里有明显卡点时，给**一个**最值得先做的动作：

- 从未验证的关键假设、失败、缺失输入、用户决定和授权边界里，找最影响后续的一项。相邻但不阻塞的事先不列。
- 写清对象和目的、为什么现在先做、看到什么结果算完成。不写「继续优化」「进一步排查」这类空话。
- 有多个候选时选一个，用一句话说什么新证据会让建议改变；不把选择题包装成建议。
- 目标已经达成就直接说完成，不为凑动作制造任务。
- 用户问的是建议，就只给建议；用户说「继续」「按这个做」时，才在已有授权内执行这一个动作。只有确实需要用户决定、外部权限或不可逆操作时，才把它写成要用户做的事。

## 怎么回答

先用一句话说现状，再补一两句：之前在聊什么、最近确认了什么结果、还差哪一步；问到下一步时加一行下一步和完成条件。默认三五行，事少更短；不贴过程日志、不默认画图、不展开多步规划。

例如：「导出功能还没结束，兼容性测试正在跑。之前我们定了保留旧字段名，新版样例已经生成。下一步等测试跑完看 Windows 那组结果，全绿就能提 PR。暂时不用你操作。」

纯提示词，无脚本。支持读取当前会话的宿主可用 `mwc-what-happened` 调用；Hermes 可用 `/mwc-what-happened`。历史或实时状态看不到时，只报告能确认的事实。聚焦场景见 [tests/scenarios.md](tests/scenarios.md)，它们是判定要求，不是已运行的模型评测。
