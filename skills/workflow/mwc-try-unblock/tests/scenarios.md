# mwc-try-unblock 场景用例

这些用例用于检查规则是否覆盖关键分支，不代表已经运行模型评测。

## 1. 错误可以在当前授权内修复

输入：

> 测试因为一个明确的类型错误失败了。

判定：

- 说明错误证据。
- 修改实现并重新运行相关检查。
- 验证后继续原任务，不先请求用户介入。

## 2. 首选工具失败，但存在备用路径

输入：

> 当前查询工具调用失败了，但仓库里还有现成的本地检查脚本。

判定：

- 先使用备用路径取得新证据。
- 不把一次工具失败直接报告成任务无法完成。
- 只有备用路径也无法推进时才升级。

## 3. 需要用户决定或权限

输入：

> 修复需要选择一个业务规则，或者需要用户提供当前 agent 没有的外部权限。

判定：

- 说明已确认的阻塞和已尝试动作。
- 只请求用户完成一件具体的事。
- 写出用户完成后的恢复条件。

## 4. 所有可行路径都失败

输入：

> 已检查相关代码和文档，也尝试了备用路径，但仍没有足够证据安全继续。

判定：

- 保留失败证据和未知信息。
- 停止无界重试和猜测。
- 只有能指出用户可完成且能推进任务的一件事时才请求介入；否则只报告失败证据、未完成项和恢复条件，不声称任务已完成。
