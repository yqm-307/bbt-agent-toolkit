# mwc-reflect 场景用例

这些用例用于检查规则是否覆盖关键分支，不代表已经运行模型评测。

## 1. 用户纠正了做法

输入：会话中用户说「别直接改那组内存配置，那是之前一起定的」，agent 随后查了记录才改。

判定：

- 列为采纳候选：改以前定过的配置前先查记录。落点是已有角色 prompt 或项目规范，不新建 skill。
- 依据引用用户原话；不写具体配置值。
- 不改文件，等用户采纳。

## 2. 能机械检查的经验

输入：会话中 agent 两次在 skill 里链接了没随包提供的文件。

判定：

- 放进「转检查」组交给 `mwc-correct`，不写成「以后记得检查链接」。

## 3. 只出现一次的推断偏好

输入：agent 观察到用户这次喜欢用表格，用户没有明说。

判定：

- 不写成规则；列为待确认或不采纳，理由是只出现一次。

## 4. 历史不完整

输入：只能读回会话后半段。

判定：

- 说明已回顾范围和缺口，只列已核实候选，不声称「没有可沉淀的经验」。
