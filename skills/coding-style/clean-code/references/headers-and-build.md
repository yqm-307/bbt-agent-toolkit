# 头文件、构建与大型语言特性

## 自给与依赖

头文件独立包含可编译，包含直接使用的符号声明。`.cc` 先包含对应头，再包含它自己使用的其他符号；不依赖传递包含。不要在头文件全局写 `using namespace`，不要前向声明不拥有的第三方或标准库实体。
项目自有类型的前向声明仅在依赖/编译成本值得时选择，不为了前向声明把值成员改成动态分配。

**声明与实现默认分离**：声明（类定义、函数签名）放头文件，实现放对应 `.cc`；不把非平凡函数体写在头文件里。移动实现主要降低消费者重编译成本与暴露的实现依赖；需要真正隐藏成员或稳定 ABI 时需另用 pimpl 或抽象接口。`inline` 是 ODR/链接说明符，不保证编译器内联。

例外（须有充分理由）：
- 模板函数/类的完整定义必须对客户端可见，可放在头文件末尾的 `// Implementation` 区或单独的 `_impl.h`；仅在单个 `.cc` 实例化的模板可留该文件。
- `constexpr` / `consteval` 函数、`inline` 变量、`static constexpr` 数据成员、`= default` / `= delete` 成员、成员模板等由语言强制要求在客户端 TU 内可见的实体，须保留在头文件中。
- 确实平凡的 getter/setter（一行，无副作用）可在类体内定义；类体内定义隐式为 `inline`，不另加条件。
- header-only 基础模块（纯算法、类型工具、无状态小组件）可完整实现在头文件；目标仓若有明确的 header-only 策略，按该策略执行。

不可接受的模式：在头文件直接写普通函数体（工具函数、辅助函数、有状态初始化逻辑等），即使当前只有一个 `.cc` 包含它。

## 特性选择

语言版本、RTTI、异常和测试入口来自目标构建配置，不把一个仓库的 C++17、`-fno-rtti`、CMake 或 Boost.Test 推广成通用要求。禁止为满足风格擅改构建开关。

- 模板用于确有多类型复用的代码；普通函数足够时不用元编程。错误信息、实例化成本和调用点理解成本也算成本。
- `auto` 在初始化器明显、迭代器繁琐或避免错误时合适；不要隐藏影响所有权、数值范围的关键类型。
- 重载应语义一致，运算符含义应符合通常预期。默认实参不用于虚函数，不藏动态副作用。
- 接口、工厂与继承是否值得按 [职责与抽象](design-principles.md) 判断，不在语言特性页另设一套门槛。
- 宏只在语言机制不能表达时使用，使用项目唯一的全大写前缀；避免重复求值、不平衡语法和生成公开 API。
- Google 对 C++20 modules、标准库部分设施有额外限制；触及限制或新语言特性时查上游对应章节，不凭“现代 C++”一律允许，也不凭本 skill 未列出就禁止。

## 验证

使用真实目标标准编译，保持无新增警告；不要用新增 `-Wno-*` 掩盖问题。验证修改的公开头可独立包含，模板有实际实例化检查。新测试按目标项目的发现/注册机制加入，选择覆盖成功、错误、边界的最小充分测试。
代码格式检查不证明语义正确；编译成功不证明并发安全。只声称真实执行覆盖的部分。

怀疑旧构建产物或切换依赖版本时，使用独立构建目录，或先证明已有目录与当前源码、依赖一致；不把源码时间戳当成依赖身份。CMake 的 `<包>_DIR` 缓存可能保留旧路径，仅改 prefix 或得到 `no work to do` 不证明已切换；核对 cache、实际编译/链接和必要的加载路径，不要求无疑点时每次重建。
