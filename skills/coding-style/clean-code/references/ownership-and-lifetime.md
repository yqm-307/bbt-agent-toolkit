# 所有权、对象不变量与错误边界

## 值与资源

优先值语义和自动存储期；需要动态对象才用 `unique_ptr`，确需多方共同延寿才用 `shared_ptr`。裸指针和引用可借用，必须明确可空性、使用期限和失效条件。
`shared_ptr` 保证控制块管理的寿命，不保证被指对象线程安全；环形共享用弱引用或改所有权图。不要把裸指针重复包装成独立控制块。

资源使用已有 RAII 包装；底层封装内部的 `new`、`delete`、`close` 并非一概禁止，但每条失败/早退路径必须有唯一可靠的释放责任。普通调用方不要重复手工清理。值对象或智能指针能解决时不另建管理框架。

## 构造与复制

- 简单对象直接构造，不强制工厂、私有构造或堆分配。
- 构造建立可用的不变量，不调用虚函数。构造不能报告可恢复失败且项目不使用异常时，考虑返回明确失败结果的工厂；避免调用者必须记住再 Init 才可用的半成品。
- 单参数转换构造及转换运算符通常 `explicit`；复制/移动构造不是机械加 explicit 的对象。
- 默认让成员负责资源（Rule of Zero）。资源语义需要时明确删除复制或定义移动；不为所有类型机械补齐五个特殊成员函数。
- 多态删除需要安全析构接口；覆盖虚函数写 `override`，不要重复写 `virtual` 与 `override`。

## 参数和返回

优先返回值。不可空借用通常引用，可空借用用指针；小型输入按值，大型只读输入用 const 引用。输出参数放后，说明失败时是否保持原值。

多结果或可失败的操作，建议多用 `tuple` / `Result` 返回，少用多个出参；调用点用 `auto [v, err] = F();` 接收。同一操作建议同时提供两种兼容风格，行为一致，只是结果交付方式不同（建议性，不要求每个接口都补齐）：

```cpp
errcode TryRead(Buffer& out);           // 出参版：复用缓冲，热路径少一次移动
tuple<Buffer, errcode> TryRead();         // 返回值版：配合结构化绑定
errcode Read(Buffer& out, opt);           // 带选项的阻塞版，同样两种
tuple<Buffer, errcode> Read(opt);
```

返回值版直接调用出参版实现，避免两份逻辑；错误码在 `tuple` 中永远放最后（`ErrTuple` 这类错误在前的写法属存量，新接口不沿用）。

view、span、指针、引用不延长底层对象寿命。保存输入供调用后使用时，优先持有值或所有权；仅把引用改成指针不能修复悬空。

## 回调

逃逸 lambda 优先显式捕获。复制裸指针、`this`、view 仍然只是借用；证明对象活过任务，或捕获值/所有权。同步算法中短小的默认捕获不自动构成问题。

```cpp
// 形状示例：仅表达捕获策略，不假定某个队列 API。
// 好：任务拥有字符串数据。
auto task = [text = std::string("ready")] { return text.size(); };
// 坏：返回 [&local] 的任务，local 已随创建函数退出而销毁。
```

## 错误与 noexcept

Google 默认不使用 C++ 异常；集成已有使用异常的代码，不擅自禁用异常或改写公共协议。错误码、Status、optional 各有表达边界，不在通用规范里强制 `0/-1/1` 或新增 Abseil 依赖。
边界检查失败应有可观察结果，不只日志、不吞错。修改状态先验证；多步操作需说明失败后保持或回滚到什么状态。
`noexcept` 是不抛承诺，不是性能装饰；检查所有可调用路径，包括分配、锁和用户回调。析构不得让异常逸出。
