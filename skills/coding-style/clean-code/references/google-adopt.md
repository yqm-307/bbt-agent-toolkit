# C++ 来源、采纳边界与维护审查

仅核 C++ 规范来源、例外或维护时读取；不是所有任务的额外必读。

来源：[Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html)。重点章节：Naming、Formatting、Header Files、Classes、Functions、Ownership and Smart Pointers、Lambda Expressions、Exceptions、Static and Global Variables、Coroutines。在线原文未固定快照，触及新限制时查对应原文，不凭“现代 C++”一律允许/禁止。

## 采纳边界

- 语义基线参考 Google；团队命名/格式的唯一细则见 [命名与文件](naming-and-files.md)，是用户确认的机械习惯，不等于 Google 原文。4 空格、m_ 成员、声明列对齐等只在目标仓无冲突既有规范时作为默认，不反推迁移全库。
- 历史 `_PascalCase` 不能作为 C++ 保留标识符规则的例外；具体默认和存量迁移边界由命名页定义。
- 中文解释面向中文团队，API/标识符保留原文；不宣称 Google 强制自然语言。
- 语言版本、错误与构建协议按目标项目；不要求所有项目 C++17、Abseil Status、禁异常或某种协程。
- Google 或标准允许的其他形式不自动是安全缺陷；仅为风格不能破坏公开 API/ABI、路径和行为。已证实生命周期/同步问题不能因存量忽略。

## 维护本 skill 的审查条件

1. **入口与路由够用**：主文独立说明通用方法、权限和完成条件；C++ 分支有必读默认页与按需细则，不把所有语言正文重新塞进入口。
2. **唯一责任**：通用表达/抽象不在 C++ refs 另立规则；精确机械表只在命名页。来源、例外、正文与 references 不互相否定。
3. **可泛化**：去掉仓库名仍可判断；不固定调度时序、对象表、宏协议、错误码、线程数、停机或测试框架。不能把换名后的专用实现伪装为通用原则。
4. **不增加虚假硬约束**：不靠行数/参数数门槛拆函数，不强制工厂/接口/继承或每类独立文件。不以“跟周围”豁免标准正确性。
5. **正反例诚实**：片段标上下文，完整例编译执行；不虚构库 API。示例成功不等于生产并发、效果评测或跨模型收益。
6. **证据匹配变更**：结构、引用、许可、原来源可恢复；语义变化做旧新独立上下文对照，实跑与未覆盖项记入变更说明，不用主观评分替代机械检查。

代表场景：普通小类不凭空加工厂；异步捕获/volatile 找寿命与同步证据；已有公共返回码接口不自动改协议；只优化性能先查瓶颈；非 C++ 请求不套本页规则。
