# SOUL 校准：可直接套用的模板

三份模板，按需复制后改占位符：挖 bad case 的公共说明、用户视图骨架、独立审查包。

## 1. 挖 bad case 公共说明

所有方向的子代理共用这一份，只是各自的方向名不同。

```markdown
# Bad case 挖掘：公共说明

目标：从 <角色> 最近 <N> 天的真实会话里，找出浪费或过度的执行流程。只收集，不提优化方案，不改任何东西。
典型例子：<用户原话转述的一例>

## 数据
- 会话索引（先看它）：<索引文件路径>，列：id, source, parent, started, title, msgs, tool_calls, api_calls, in_tok, out_tok, n_children, top_tools。按指标挑候选，不盲扫。
- 原始会话库（只读）：<路径>。只读打开；只按会话 id 查消息，不做全表扫描；关键词检索用全文索引。
- 命令加低优先级和超时；不并发起多个大查询。

## 什么算 bad case（同时满足）
1. 有真实证据：会话 id + 消息 id（或时间）+ 实际工具调用（次数、路径、命令）。
2. 存在明显更省的路径，并给出依据；核实不了的标「推断」。
3. 浪费可感知：多出的调用数、token、时间、打断次数，粗估即可。
不算：合理的谨慎（生产变更前确认、安全检查）、用户明确要求的步骤、一次性小试错。

## 输出：<目录>/<编号>-<方向名>.md
- 采样：看了哪些会话、怎么挑的、没看什么
- 每条：会话与消息范围 / 用户要的 / 实际发生 / 更省的路径（事实或推断） / 浪费估计 / 可能诱因 / 置信度
- 每方向最多 6 条，按浪费大小排序；最多深读 12 个会话；其他方向的线索只写一行带过。

## 红线
- 除了写自己的输出文件，不修改任何东西；不做 git 写操作。
- 报告里不出现凭据和内网地址，需要时写 `<redacted>`。
- 没找到就写没找到，不虚构。
```

Hermes 示例：会话库是 profile 目录下的 `state.db`，用 `sqlite3.connect('file:<path>?mode=ro', uri=True)` 只读打开，全文检索表是 `messages_fts`。

汇总表的列：主题 | 条数 | 最典型一例 | 可能诱因 | 现稿是否已覆盖。另附一张去重清单，记录原条目、会话和所属主题。

## 2. 用户视图骨架

```markdown
# 用户视图（<日期> 整理）

用途：SOUL 中「我所了解的用户」和「风险决策」由此提炼。
来源：<长期记忆检索 / bad case 汇总 / 本次会话>
局限：<接口失败、非全量等>

## 在意
| 取向 | 依据（日期、会话 id、原话） |

## 反感
| 取向 | 依据 |

## 纠正过（背后的偏好）
| 纠正 | 背后的偏好 | 依据 |

## 定过的（涉及风险，仍有效）
| 决定 | 依据 | 落到 SOUL 哪一行 |

## 长期在推进
- <方向>：<依据>

## 已推翻的旧记忆
- <旧说法> → <新说法>（<依据>）
```

## 3. 独立审查包

审查者必须没参与编写，只读，唯一允许写的是审查报告。

```markdown
被审对象：<候选稿路径>
对照：<改前版本>、<用户视图>、<移出清单>、<正式版（只用于抽查安全节未改）>

背景：<角色是什么、文件如何加载>。用户这次的要求：(1) … (2) … (3) …

硬约束（违反即阻塞）：
- 「边界与安全」原样保留，其他条文不得放宽它。
- 以下实质约束不得丢失：<逐条列出>。
- 受保护文件的独立审查、授权类决定（提交推送、重启共享服务、改运行配置、写长期记忆）不能因改写而消失。
- 除宿主适配一节外，不写具体工具名。

重点检查：
1. 用户的每条要求是否满足。
2. 内容丢失：逐项对照改前版本，列出被删、且新稿和移出清单里都没有的实质内容，只报会改变行为的。
3. 矛盾与歧义：新稿内部、新稿与安全节之间（如「自主推进」与「风险决策」、「自己核对」与「不自审放行」）。
4. 依据：对用户的每条描述能否在用户视图里找到依据；有无编造或夸大。
5. 可执行性：每条能否改变具体选择；有无口号。

停止条件：审完就停；工具调用不超过 <N> 次；不提范围外的改进，阻塞问题除外。
输出：报告写到 <路径>，不超过 80 行。结构：结论 → 问题清单（等级、位置、原文、问题、可直接替换的最小修改文本）→ 内容丢失核对 → 已确认无问题的项。
最终回复只返回 JSON：{"verdict": "可落盘|修改后可落盘|不可落盘", "blocking": n, "suggested": n, "optional": n, "report_path": "..."}
```
