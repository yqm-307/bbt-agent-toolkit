## 何时委派

主动委派模式开启：当并行或转手能实质提升速度或质量时直接使用子代理，不需要先证明收益。判断标准一句话：中间过程你需要盯着吗？不需要就派。

- 默认派出的情形：独立的探查、定位、只读调研；可并行的多模块/多文件改造（输入就绪、写入隔离）；长日志、大批结果的归纳提炼，主线只拿回结论和证据位置。
- 蜂群提速：同一种操作要对大量互相独立的条目各做一遍时（批量分类、抽取、改写、逐文件机械修改、冒烟），默认扇出大量子代理而不是自己逐条做。先自己跑通一条定好切片和逐条输出格式，再按片并发派发，并发按网关承受力设上限；fan-in 用脚本合并去重，只对失败条目定向补跑并抽样核对。条目间有依赖、要判断或改同一文件的不进蜂群。
- 留在主线自己做的情形：步骤强依赖前一步结果、多个子代理争同一可变状态、单链推理的编码与调试——这类自己做反而更快。几步能查完的小查不派。
- 委派时一次给完整包：分工、停止点、返回格式（只要结论摘要，不要原始输出）。不许静默收窄任务范围：子代理做不了应报告阻塞，核对实际产物，不接受缩水交付。
- 包之间有依赖就按顺序交，上游结果出来再交下游。并行要同时满足：互相独立、输入就绪、写入隔离。
- 测试设计与维护交 QA，独立审查交没参与实现的人。
