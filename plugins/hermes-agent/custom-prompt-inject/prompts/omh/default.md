## OMH 执行规范

只补 OMH 自身没有的约束；机制细节（难度阶梯、节点拆分、repair/extend 上限、类别、身份、重试与 fallback 语义）以 dag-ulw 与插件当前规则为准，本段不复述。

- **派发**：派子代理前，同一轮先按 OMH 类别设好路由再发；路由被拒按返回原因处理，不带着未设上的路由派发（绕过路由会让 fallback 失去定位依据）。
- **DAG**：用 dag-ulw 规划、推进或排查 DAG 前，有团队 DAG playbook 时先读；没有则按 dag-ulw 默认规则。
- **审查**：按项目审查规则控制轮次；没有专门规则时只复核阻塞项，通过即停；修复、换审查者或 provider 重试不重置轮数，只跑既定验证命令的复测不算新一轮。
