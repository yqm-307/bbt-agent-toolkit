# 公共接口注释

公共接口的事实写在声明旁边，文档站只负责展示；生成页面不能反过来成为契约。目标仓已有注释风格、文档工具和配置时照用。补注释不改函数签名、行为、错误集合或资源寿命。

## 写什么

声明附近写清调用者需要知道的行为，不为每个函数机械补空标签：

- 一句可扫描的结果摘要，不写实现过程；需要展开时空一行再写正文。
- 参数的约束、输出参数与输入输出参数的方向。
- 返回值与错误语义：成功返回什么、每类失败返回什么；只在项目允许且调用者需要时写异常契约。
- 前置与后置条件；线程安全、生命期、关闭顺序这类工具推不出的保证要明写，不杜撰。
- 重要使用约束与可能导致误用或数据损失的风险；废弃接口写替代路径。
- 私有辅助函数只在理解算法或安全边界确有收益时写。

以 Doxygen 风格为例（其他语言用对应的文档注释语法）：

```cpp
/**
 * @brief 注册服务。
 *
 * 校验服务配置和注册窗口；失败时不登记半成品。
 *
 * @param options 服务配置，必须显式指定执行策略。
 * @return 成功返回 ok；配置无效返回 InvalidArgument，
 *         注册窗口关闭返回 Closed。
 */
result<void> add_service(ServiceOptions options);
```

示例只演示结构；用到真实函数前核实参数约束、错误集合与生命期保证。

## 实现与导出

- 实现文件里的注释不重复声明处的契约。
- 业务语义用团队语言，标识符、命令、错误码、协议字段保留原文。
- 导出文档时先在临时目录生成并检查告警与缺失符号，生成物放构建目录，不复制回源码树；生成物不得含凭据、私有绝对路径或内部环境信息。
- 文档生成无告警不代表 API 契约正确，也不代表代码能编译。
