# 编码流程

本文约束把已明确的契约做成可维护实现的工作流程；语言规范、格式、注释与审美按目标仓声明采用的规范，未声明时按该语言主流规范与仓内既有写法。

## 何时读

实现或修改代码、修复缺陷、跨模块重构，或需要把设计交付给编码包时读取。本文只负责实现流程，不替设计者补规格，不接管测试设计和独立审查。

## 开工核对

开始开发前核对实际依赖及版本、当前分支与工作树状态、目标基线和是否基于 latest。依赖包括子模块提交、包管理锁文件、系统库和上游版本；版本不明或不符先报告。发现落后、不一致、冲突风险或未提交改动时，不自行 pull、rebase、merge、reset、stash 或覆盖，先报告并按项目规则处理。

把目标、验收、允许写入范围、已冻结的设计和不做事项固定下来。读取目标仓 `AGENTS.md`、相关代码、真实调用者、失败路径、构建入口和门禁；只查会改变实现判断的未知项，够支撑决定就停。

## 一次改动的最短路径

1. **先看调用关系**：沿创建、持有、借用、异步执行、取消、关闭、错误和释放路径找共同责任。看到多个调用点有相同失败，不要先逐点加条件，先判断是否有共享根因。
2. **再确认设计**：有目标类图和设计范围时按冻结契约实现；发现接口、所有权、失败语义或并发模型不成立时停下交回，不边写边改方向。小改动可在同一包内完成设计与编码。
3. **选择最小实现**：优先已有辅助函数、标准库、平台原生能力和已选依赖，最后才写新代码。没有真实消费者的抽象、配置、扩展点或依赖不加入。删除重复机制前确认消费者与契约仍成立。
4. **保持语义完整**：接口、错误、取消、关闭、容量、未知结果、资源归还和观测责任不能因少代码被删掉。网络写操作说明幂等、超时、重复、乱序和结果查询；资源明确 owner 与关闭语义。
5. **按意图组织函数**：入口函数保留阶段骨架，阶段函数用意图命名；锁的持有范围留在入口，辅助函数不要各自改变锁序。纯结构拆分保持 early-return、状态副作用位置和锁序不变；需要改行为时另做一次改动。
6. **同步稳定文档**：代码对应的公共接口、示例和稳定说明随同一编码包更新，当前概念直接写成当前事实，不在旧定义后追加历史补丁。

正例：修改队列入队前，先找到生产者、容量检查、等待者、取消路径和释放点，再修共享收口处；入口函数保留“门禁 → 采样 → 决策 → 提交”的阶段骨架。

反例：看到两个调用点都失败就各加一个条件，未检查它们是否共享同一责任缺口；或者为了避免一个小函数新增万能基类和全局事件总线。

## 最小自验与交付

编码包只做证明本次改动成立的最小检查：项目要求的编译、最小功能检查和直接耦合模块的已有检查。任务书点名命令时只跑点名命令；完整测试、回归、压力和性能检查交给 QA 或项目门禁。失败带复现命令回交，修复后先复测失败项；不降低断言、删用例或靠重试凑全绿。

交付报告写清结论、分支和提交状态、改动文件、实际命令与结果、未验证项、建议 QA 覆盖和范围外观察。未跑、跳过、失败和通过分别表述；本地结果不写成 CI 结果。达到编码者能交付、验收一句话说得清且新增改动不再改变结论时停止。

## 边界

不夹带无关重构、全仓格式化、新工具链、CI 改写、依赖安装、生产操作或权限变化。设计、测试、独立审查、发布和合入由对应职责承担；超出授权的需求交回协调者。
