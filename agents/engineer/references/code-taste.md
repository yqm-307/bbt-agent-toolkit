# 代码品位：显式机制，克制抽象

职责做窄，语义做实；机制显式，封装克制；复用优先，升级有据。目标是降低总的理解与修改成本，不是最少行数、零注释或最多复用。目标仓的契约、语言标准与工具配置优先于本文。

## 改动的阶梯

理解需求与真实调用关系后依次考虑：不需要做 → 已有实现 → 标准库 → 平台原生能力 → 已安装依赖 → 直接实现。停在第一个满足需求和边界的台阶，不为走阶梯做无界调查。

- 共享根因在共同位置修；先核调用方的真实差异，不因表面相似强行合并。
- 减少文件、依赖和跳转是手段，不以最少行数牺牲可读性、求值语义、错误处理或测试。
- 不能省：信任边界校验、防数据丢失、安全、明确需求与必要的行为检查。非平凡逻辑至少保留一个能区分关键错误的可运行检查。
- 刻意采用有上限的朴素方案时，在代码注释写明适用边界、到达上限时的表现和升级信号；“以后优化”不算说明。

## 命名与接口

- 用已有领域术语，同一概念同一词；名字匹配作用域，单位、端点和副作用可辨认。读取操作不能悄悄创建、消费或持久化。
- 调用点有歧义时，优先现成类型、枚举、结果结构、具名参数或常量；不为每个值包类型，不用任意字符串替代有限选项。
- 参数多、布尔标志只是检查线索，不是缺陷。已发布接口不能因审美变更，也不能只凭仓内无调用判定可删。

## 流程与函数边界

- 一个函数表达一个逻辑操作，按语义而非行数划分。早退只在保持全部可观察行为时采用：错误集合、副作用的次数与顺序、公共失败语义都不变。
- 提取函数须命名独立概念、隐藏细节或统一同一规则；只转发参数、增加跳转的提取无益。不把条件求值提前成无条件执行。
- 不设函数行数或参数数量硬阈值，不强制 getter/setter、接口、设计模式或 DRY。
- 不以整洁为由把错误码改成异常、借用改成复制，或删必要的空值检查。行为保持优先于审美。

## 职责与抽象

模块难懂时，先看它是否兼管了别人的生命周期、策略、兼容或资源。复杂度由拥有必要信息与控制能力的层承担：底层提供可组合原语，上层负责自己的策略。

提取抽象前问三件事，任一没有依据就保留直接写法：

1. **稳定语义能命名吗？** 多处是否必须随同一知识或不变量一起改变，而不只是长得像？
2. **消费者少知道细节了吗？** 是否仍保有完成真实工作所需的控制？
3. **总成本下降了吗？** 一起看调用点、实现、错误处理、测试与调试，而不只数重复行。

直接调用现成后端足够时，不加 Port/Factory/Manager 链；为稳定边界或真实替换需求设接口，不为想象中的后端数量建框架。单实现、固定容量、串行执行等有限方案满足需求即可，但要写明适用范围。

## 所有权、错误与资源

- 每个资源有唯一拥有者和明确的关闭语义；每条失败与早退路径都有可靠的释放责任。优先值语义和语言提供的自动释放机制（RAII、`defer`、`with` 等）。
- 借用（引用、指针、view、slice）不延长对象寿命。调用后还要用的输入，持有值或所有权。
- 构造即建立可用的不变量，避免“必须再调 Init 才能用”的半成品。
- 边界检查失败要有可观察结果，不只写日志、不吞错。修改状态前先验证；多步操作说明失败后保持或回滚到什么状态。
- 逃逸的回调显式捕获；捕获裸指针或引用仍只是借用，要证明对象活过回调。

## 并发与异步

- 每份共享可变数据说明谁访问、由哪把锁或哪种原子协议保护。多个字段共同维持不变量时，分别改成原子变量不保证整体一致；默认用清楚的锁，有证据的瓶颈才考虑无锁。
- 锁保护短临界区；不持锁调用可能挂起、阻塞或重入的未知代码。
- 等待与通知的目标：完成事件不丢、同一工作不重复恢复、状态与寿命在发布前准备好。条件变量用谓词等待；取消、超时、正常完成的竞争要有唯一的完成与清理责任。
- 不在另一执行流仍使用对象或运行栈时销毁它；停止投递、取消、等待在途任务、释放依赖的顺序按契约验证。
- 只有确有竞争才引入状态机、代际号或取消协议；引用计数、原子字段或日志本身不是完整协议。

## 注释

- 含混能用准确命名或直接写法消除时，先改代码；删逐行翻译、装饰性分隔和开发流水账。
- 保留契约、单位与边界、不变量、所有权、并发时序、复杂算法摘要和非显然的取舍。
- 一处事实一处说明；代码变更同步更新注释。注释与代码冲突时先核契约和测试，不用实现覆盖意图。

## 完成前自查

名字匹配行为；职责与控制流清楚；错误、资源、异步边界可靠；必要注释保留；验证覆盖了声明的内容。伪代码不编译，示例通过不证明真实系统的并发与性能。
