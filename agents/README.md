# agents

可在任意项目复用的协作身份：每个都是一名与具体项目无关的优秀工程师，进入哪个仓就按哪个仓的规范干活。个人助手画像、用户偏好和私有接线不收录。

## 目录约定

```text
agents/<role>/
├── AGENTS.md      # 唯一身份正文，frontmatter name 与目录名一致
├── references/    # 正文引用的方法与资料
└── resources/     # 需要用到的工具、配置模板、脚本
```

- **自包含**：正文和资料只引用本身份目录内的文件，不链接仓库其他目录（包括 `skills/`），也不依赖某个具体项目。整个目录拷到别处就能用。
- **只放角色方法**：身份目录写这个角色怎么干活（流程、判断、边界）；「代码长什么样」的语言规范与审美不进身份目录，由目标仓声明采用（本仓 `standards/` 是一套可选的通用规范），身份正文只写「按目标仓声明采用的规范」。
- 一份方法只属于一个身份，不在多个身份间复制；`skills/` 可以链接身份资料，反过来不行。

## 身份与 DAG 节点的对应

多智能体 DAG（如 OMH `dag-ulw`）里的节点按「谁能独立交付、独立验收」分配身份，不按读、写、编译、测试这些动作拆。协调者（主会话）负责建图、派发、结算和最终回读验收，本身不是节点，不在此收录。

| 身份 | 承接的节点 | 产物 | 不做 |
|---|---|---|---|
| [architect](architect/AGENTS.md) | 调研+设计（读现有代码与定新形态合为一包）；目标一眼清楚的小改动不单设 | 目标类图 + 设计范围（改什么、不改什么、冻结接口、编码切分） | 不写产品代码 |
| [engineer](engineer/AGENTS.md) | 编码包（含编译）、失败后的修复节点；代码对应的文档随同一包 | 代码、编译结果、交付报告 | 不跑成套测试，不改断言 |
| [qa](qa/AGENTS.md) | 改动前基线、依据契约的用例设计（可与编码并行）、收尾测试与验收节点 | 用例、执行结果、失败复现命令、逐条验收结论 | 不改产品代码，缺陷交回 engineer |
| [reviewer](reviewer/AGENTS.md) | 独立审查节点：受保护文件、公共契约、并发等待/唤醒/取消、对象寿命、安全边界 | 分级审查报告 | 只读，不修 |

不单设身份的工作：

- **性能测量**归 qa，按需加载性能对照方法；**文档**与对应代码同包，归 engineer。
- **验收**不另设身份：验收节点只要求不是实现者本人，由 qa 跑真实命令，协调者回读产物。
- 视觉、运维等领域按需另立身份，不进入通用开发 DAG。

典型形态（细节以目标仓工作流规范为准）：

```text
基线(qa) + 调研+设计(architect)
   │
   ├─ 编码(engineer) ─┐
   └─ 用例设计(qa) ───┘
   │
收尾测试/验收(qa)
   │  └─ 失败 ─> 带复现命令回到 engineer 修复 ─> 先复测失败项
   │ 通过
独立审查(reviewer)
```

## 接入

本目录只提供正文，不自动改写任何宿主配置；下列接线由使用者在自己的环境中完成。

- **常驻 profile**（reviewer 除外，它只经子代理派发）：宿主支持以文件作为身份正文时（如 Hermes profile 的 `SOUL.md`），用软链指向本仓文件，避免复制：`ln -sfn <toolkit>/agents/<role>/AGENTS.md <profile 目录>/SOUL.md`。改变软链前确认原目标，保留回滚路径。
- **子代理派发**：多数宿主的子代理不继承派发方的身份，派发时把对应 `AGENTS.md` 完整正文随委托 context 附上，或让执行器先读取该文件、读不到返回 `NEEDS_CONTEXT`；只给角色名不算交接。
- **OMH 身份路由**：可在 OMH 的 `routing/identities.json` 为身份注册一条记录，`prompt` 只写「读取 `<toolkit>/agents/<role>/AGENTS.md`，读不到返回 NEEDS_CONTEXT」，`model_chain` 由使用者按自己的路由配置填写。字段以所装 OMH 版本的 schema 为准。

`<toolkit>` 是本仓检出的绝对路径；软链指向的检出需跟随 `main` 更新，指向未合入分支的正文不算生效版本。
